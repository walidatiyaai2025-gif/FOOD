# V2 #2597 — P267 Field Operations Customers authorization and data isolation

- **Source:** `FOODEX-Unified-RBAC-ERP-Sidebar-Discussion-2026-11-09.docx`, P267; master #2503.
- **Scope:** existing `Field Operations → Customers` page; canonical route `admin.field-operations.customers` (`GET /admin/field-operations/customers`), `FieldOperationsController::customers`; no new route or Sidebar item. PR target `Foodex_V2` only.
- **Placement:** Reuse existing `field_operations` group, `field_ops_customers` child and existing Dashboard grid. No new screen, Sidebar or freeform technical input.
- **Navigation authority:** both `customers.view` and `drivers.b2b.view` permissions and existing Dashboard admission are required on HTTP. Sidebar `routeItemAll` reflects the same rights; inactive, roleless, Retail-only and missing-grant actors cannot enter.
- **Data security defect:** original P267 page enumerated every latest `van_visits` row, including B2C Retail and other B2B stores, and attached any active van assignment for the same representative, leaking foreign-store van/territory/customer identity. Concealment by Sidebar did not protect the HTTP response.
- **Fix:** filter `van_visits.customer_type=b2b` and active, authorized B2B stores **before** grouping latest visit IDs. Group per `customer_id, store_id` to prevent another tenant's newer visit from masking a legitimate own-store record. Match the existing Van Visits rule permitting legacy null store only for global Wholesale operations roles. Resolve Van assignments through authoritative `warehouses.store_id`; associate only the assignment for the same visit store. A missing warehouse mapping fails closed (do not guess a store from representative identity). Financial context remains independently guarded by `finance.view` and the visible visit store.
- **Permission + tenant scope:** global Super Admin/B2B Admin/Operations/Finance B2B roles can review all active B2B stores; other permissioned viewers see only B2B stores linked to their user-store assignment. Retail stores, Retail-only roles, cross-store Van metadata and other apps' visits must not appear.
- **UI/UX + localization:** canonical existing grid, responsive foodex operations table, existing AR/EN labels, RTL/LTR and pagination unchanged. No route/layout duplication. Loading-empty state stays `field_operations.no_customer_relationships`. No new user-facing untranslated strings.
- **Customer app:** no change to API `/api/v1`, auth/identity, storefront/order payload, or Flutter code. Customer-specific reads unchanged.
- **Driver app:** no change to B2C Driver dispatch/status/proof, API or Flutter; the Dashboard P267 list intentionally excludes Retail Driver-only records.
- **Van app:** B2B Van visits lifecycle and API remain unchanged; this Dashboard read only restricts visible B2B store rows and assignments. No Flutter, offline replay or assignment mutation changed.
- **Required automated evidence:** `php artisan test --filter=V2FieldOperationsCustomersAuthorityTest`, Laravel full suite, PHP syntax/Pint/PHPStan/security, AR/EN, exact-head Repository Policy + FOODEX V2 Isolation + FOODEX Required CI (including MySQL/Redis fresh-install/upgrade/recovery).
- **Negative cases:** same customer across multiple B2B stores, newer foreign visit, B2C visit, null-store legacy visit for scoped viewer, foreign representative's Van assignment, roleless/inactive/Retail-only actors and missing either required permission. All data assertions read actual rendered controller paginator, not just text matching.
- **Manual acceptance:** viewport/real UAT deferred to V2 final master #2503 / UX #2750 per owner's 2026-11-10 decision. No claim of production deployment or device acceptance.
- **Release/security:** no `main` merge, release, tag, installer publication, production update or mobile APK release authorized here.
