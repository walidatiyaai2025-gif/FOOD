# V2 #3581 — Notifications Center literal search acceptance

- **Source:** FOODEX V2 / #2503, existing Notifications Center #2678. Implementation PR **Foodex_V2 only**; no `main`, tag, deployment or production promotion.
- **Actor:** authorized Super Admin with `notifications.manage` via existing `management.dashboard` route guard. A non-Super-Admin is denied even for crafted `q`. Existing navigation/route and permissions are unchanged.
- **Entry point:** Administration → Notifications Center, `GET /admin/notifications?q=...&status=...`; no new UI or navigation item.
- **Root cause:** four AR/EN title/body predicates used bound but unescaped user text in SQL `LIKE` patterns. Text containing SQL wildcard `%` / `_` could broaden authorized search results. This is search accuracy, not evidence of an authentication or tenant bypass.
- **Fix:** escape literal `!`, `%` and `_` in that order and use `LIKE ? ESCAPE '!'` for the four fixed notification columns. Query parameters remain bound; preserve status filtering, pagination, order and page-level AR/EN/RTL-LTR behavior.
- **Regression:** `backend/tests/Feature/V2NotificationLiteralSearchTest.php` runs real authenticated Laravel HTTP searches for four individual AR/EN fields in both locale modes; a literal `%_!` positive match and false-positive lookalike are compared, normal query stays functional, draft/published status filter remains authoritative, non-Super-Admin direct HTTP is forbidden and read-only queries do not mutate notification rows. Existing `NotificationAdministrationTest` covers create/publish, live feed and API audience isolation.
- **Scope and compatibility:** Backend/Dashboard existing admin list affected; Customer, Driver and Van APIs and Flutter **not affected** — no change to public routes, notification models/JSON, targeting/dispatch or device apps. B2B remains VAN ONLY and B2C DRIVER ONLY. No migrations, app entitlements, publish/review or security policy changes.
