## Source contract and fail-closed migration

- Existing `Settings → System → System Updates` form now accepts **Update ZIP + detached publisher-signed manifest**; no raw JSON, internal signer ID, version/sha256 or release note text is typed by the operator.
- The signed sidecar uses the exact fixed set `format, signer_key_id, target_version, minimum_current_version, archive_sha256, contains_migrations, release_notes, signature`. `format=foodex-signed-update-v1`. Canonical signed bytes are generated by `TrustedUpdateSignatureVerifier::canonicalPayload` with `FOODEX-UPDATE-SIGNATURE-V1` domain separation. Maximum sidecar size 16 KiB; strictly typed and no extra keys.
- Trusted Ed25519 public key is pinned only in host-controlled `FOODEX_UPDATE_PUBLISHER_KEY_ID` and `FOODEX_UPDATE_PUBLISHER_PUBLIC_KEY_B64`, via `config/update_signatures.php`; **not** from uploaded manifest, user-provided key, URL, or environment committed in release ZIP. No test key is accepted by default. Revocation/rotation is a separately authorized host operation, not automated from untrusted ZIP.
- Before staging the ZIP or creating update history/backups, `SystemUpdateController::store` verifies the signed manifest against the host-pinned key and canonical payload. Missing/untrusted/malformed/tampered signer is denied safely. The existing `UpdatePackageValidator` additionally matches archive SHA-256 to the signed value and rejects incompatible/downgrade/corrupt ZIP; `LaravelUpdateRuntime` rejects traversal/symlinks and performs budgeted staging. This is a **Dashboard admission** gate; direct internal `UpdateManager::execute` still exists for trusted internal applications/tests, so full engine-level unsigned-caller audit remains high-risk follow-up.
- Super Admin + `Gate::authorize('system.update')`, tenant boundaries, audit, single-operation lock, database and file backups, maintenance, migrations, health checks and safe/manual rollback semantics are unchanged.
- UI is bilingual: if the host has no independently validated publisher key, Install is disabled and guidance points specifically to cPanel/environment provisioning; a PHP Sodium check or SHA-only match never certifies a release. Keys are external **Required / Host provisioned**, not preconfigured dummy data.
