## Reproduced source gap

The isolated Laravel backend previously had `backend/composer.json` but **no versioned `backend/composer.lock`**. The canonical `.github/workflows/release-factory.yml` invokes `composer install --no-dev` to stage the Setup ZIP. Without a lock, identical source SHAs can resolve different Laravel/transitive production package versions; the former backend CI explicitly used `composer validate --strict --no-check-lock`, so that delivery invariant was not enforced.

## Bounded fix

- Check in `backend/composer.lock` generated from **the existing** Composer requirements; includes the production and development dependency graph, immutable package version/source references and Composer content hash.
- Set `config.platform.php = 8.2.0` in `backend/composer.json` so the dependency solver selects packages installable on the project's documented PHP 8.2+ shared hosting minimum, even when the CI development runner is PHP 8.3.
- Backend CI now runs **`composer validate --strict --no-check-publish`**, rejecting a missing, stale or inconsistent lock; no disable-lock escape hatch.
- The canonical release factory validates the same lock **before** resolving production dependencies and building its Setup ZIP. It still installs with `--no-dev` and includes `vendor` in the exact ZIP build; production installation users are not asked to run Composer.
- No runtime application/controller, migration, permissions, `.env`, DB, secret, UI or API file is modified by this slice.

### ZIP Unicode Path extra field ambiguity (2026-11-14)

### Portable ZIP compression for cPanel/shared hosting (2026-11-14)

The original #2745 / draft #3444 **staging-only** verifier now rejects archive members that use ZIP methods other than **STORED (0) or DEFLATED (8)**. Python's `zipfile.testzip()` accepts BZIP2 (12) and LZMA (14), but these are not reliably supported by the ordinary unzip handlers available on shared hosting/cPanel. An archive passing Python CRC with an unsupported method could otherwise fail at the user's required single extraction step. The fail-closed allowlist applies to every member before decompression; no runtime, release signing or production unpacker behavior is modified. This change intentionally does not reject ordinary STORE/DEFLATE members or otherwise valid optional ZIP timestamp metadata.

### Local/central ZIP header consistency (2026-11-14)

The G004 verifier previously attested only to central-directory compression, flags and Unicode Path extra metadata. A malformed local header flags field creates the same cross-extractor inconsistency. Likewise an Info-ZIP Unicode Path alias may appear **only in the local extra field**, while the central extra field appears benign; Python CRC reads alone do not attest a unique extraction path.

### Streaming ZIP data-descriptor consistency — isolated G004 hardening (2026-11-15)

A ZIP produced by a non-seekable stream uses general-purpose bit 3 (0x08) and a data descriptor after each compressed member. Python's `ZipFile.testzip()` validates payloads against the CENTRAL directory but does not verify the descriptor CRC and sizes. One real non-seekable ZIP positive regression and three separate CRC/compressed/uncompressed descriptor-tamper cases were added using actual ZIP archives; all malicious fixtures retain valid CENTRAL CRC values. Ordinary stored/deflated ZIP handling is unchanged.
