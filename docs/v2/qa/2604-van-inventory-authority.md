## Cross-channel primary Van assignment guard (P274)

An active effective primary assignment may have been imported or persisted with a B2C Driver even though the Van runtime has B2B-only dispatch semantics. **Assigned B2B warehouse stock must never make that invalid B2C assignment legitimate.** The read-only VanInventoryReadService rejects a non-null linked driver unless its persisted `drivers.driver_type` is exactly `b2b` and `drivers.is_active` is true. Driverless supervisor-managed assignments remain usable; role/store-effective `drivers.b2b.view`, WMS `inventory.view`, assignment uniqueness, warehouse scope, and module entitlement checks are unchanged.

The issue-scoped Laravel regression creates a valid B2B warehouse and supervisor Van stock read; injects a legacy B2C driver on the same primary assignment to prove HTTP 404-equivalent service denial and zero stock writes; restores an active B2B driver to confirm a valid read; and then disables that driver to prove a second deny. Customer and Driver application/public API contracts are untouched. Van application/public API contracts are also unchanged, but incomplete Van assignment WRITE eligibility for B2C drivers belongs to #2738, and physical Van custody/stock settlement and Van mobile parity remain separate acceptance requirements (#2739/#2602/#2588).

**Still incomplete:** This is a defensive WMS read-path fix only, not a full P274 stock-custody, Dashboard HTTP/UI, AR/EN, RTL/accessibility or Van Flutter implementation. Do not merge PR #3330 or close #2604 solely on this patch, and do not waive the independent #3160 immutable Enterprise Performance gate.

## Linked driver account activation parity (P274)

The canonical assignment writer `VanRegistryService::assertActiveB2bDriver` requires both `drivers.is_active` and the referenced `users.is_active` to be true. The issue-scoped read service now applies the same independent linked-user activation check before querying WMS stock, so a disabled driver login cannot continue granting a legacy primary Van assignment's warehouse read. It remains fail-closed with 404, without changing the driver write workflow, the authorization scope, or inventory/stock-movement data.

The `V2VanInventoryReadAuthorityTest` progression now proves: legitimate driverless read, B2C driver denied, active B2B driver allowed, *the B2B driver's user disabled* denied, user reactivated allowed, and disabled driver row denied; all without stock movements. This is a Backend service security increment only. Customer: no API/Flutter change. Driver: no API/Flutter change. Van: no API/Flutter change in this patch; any user-facing stock UI/API work remains linked to #2739.

**NOT P274 COMPLETE:** This does not establish actual loaded Van stock custody, returns, settlement lineage, real Dashboard entry/HTTP route, AR/EN responsive/a11y, nor Van mobile acceptance. PR #3330 remains draft and unmergeable by source policy until those gaps and exact-final-HEAD Required CI are satisfied. Independent performance baseline approval #3160 is not waived. ## Legacy Driver-store channel integrity — 2026-11-14

The read service now checks a non-null linked Driver's persisted store through the canonical `OperationalTenantScope::storeChannel`, in addition to the driver's B2B type, active row and active user. An imported row reporting `driver_type=b2b` while referencing a Retail/B2C store is rejected with 404 before inventory retrieval. A null `drivers.store_id` retains the existing global B2B driver compatibility; a B2B driver from another B2B store is not newly denied by this check. This is intentionally not a new Driver-to-Van same-store policy or a change to the separately owned assignment writer.

The existing isolated `V2VanInventoryReadAuthorityTest` progression now tests B2C type denial, a forged B2B type backed by a Retail store (denied), correction to an authentic Wholesale store (allowed), disabled linked user (denied), reactivation (allowed), and inactive driver row (denied). It checks no stock movements were written.

Scope is limited to existing Van inventory service/test/QA files on original PR #3330. Dashboard route/AR-EN UI, physical Van custody/returns/settlements, Van Flutter parity (#2739), and exact-head Required CI/source approval remain outstanding. This is not P274 acceptance, signed ZIP/APK release, or production verification. No main, tags, releases or deployments.
